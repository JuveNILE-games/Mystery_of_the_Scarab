# Isolated Pockets are spatially detached, not selected from the main blob

The first SCARAB-014 implementation picked an Isolated Pocket's rooms from among the main level's own already-placed BSP leaves (excluded from the connectivity graph, but left sitting in their normal footprint position). Live testing showed this reads as "still part of the main blob" — a Pocket room can share a wall with an ordinary room, and the 2D preview (and eventually the 3D bake) has no way to show "sealed on purpose" versus "just no connection was ever considered," so it visually looks unchanged from an ordinary room.

We instead generate each Isolated Pocket as its own scaled-down mini-BSP pass (reusing `SplitIntoLeaves` with `RoomCount` set to a random 1-3 target and `CorridorCount = 0`), placed in a detached area to the side of the main level's bounding box with a fixed gap, never selected from the main graph's candidate rooms at all. This matches the actual design intent — a Pocket is a genuine sub-level layered alongside the main level, not an ordinary room the generator merely declines to wire up — and it simplifies `BspLayoutGenerator.Generate()` too: since Pocket rooms are never in the main candidate set, no exclusion/edge-filtering step is needed to keep them out of the connectivity graph.
